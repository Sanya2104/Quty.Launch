# Quty.Launch 🚀

**Quty.Launch** — лёгкое и модульное ядро для Android-приложений.

Проект предоставляет универсальный **WebView-движок**, API-мост между JavaScript и Android, а также готовую инфраструктуру для работы с **оболочками, хранилищем, обновлениями, логами и настройками**.

---

## 📦 Концепция

Quty.Launch — это **ядро**, на основе которого можно создавать кастомные Android-приложения без необходимости каждый раз реализовывать одну и ту же системную логику.

Ядро предоставляет готовые решения для:

* 🖥️ **Отображения интерфейса** — WebView с поддержкой кастомных оболочек на HTML/CSS/JavaScript и Web-фреймворках
* 🔌 **Взаимодействия с Android** — JsBridge для вызова Android API из JavaScript
* 📁 **Работы с файлами** — централизованное управление хранилищем через `StorageManager`
* 🔄 **Обновлений** — загрузка и установка обновлений приложения и оболочек
* 🛒 **Магазина оболочек** — каталог, установка, обновление, применение
* 📊 **Логирования** — буферизированная запись логов и их ротация
* ⚙️ **Настроек** — ориентация, полноэкранный режим, темы, язык, анимации
* 🛟 **Безопасного режима** — запуск стандартной оболочки при поломке пользовательской
* 💾 **Резервного копирования** — экспорт и импорт настроек

---

## 🚀 Возможности

### 🎨 Оболочки (Shells)

Quty.Launch позволяет полностью отделить интерфейс приложения от его системного ядра.

Поддерживаются:

* встроенные оболочки из `assets/shells/`
* пользовательские оболочки в формате `.qutyshell`, `.qsp`, `.qutyshellpack`
* ZIP-архивы с `manifest.json`
* автоматическая распаковка и загрузка оболочек
* версии, обновления и превью оболочек
* принудительная ориентация из манифеста оболочки

Оболочка отвечает за визуальную часть приложения, а Quty.Launch предоставляет ей необходимые API.

---

### 🔌 JavaScript API — JsBridge

`JsBridge` обеспечивает взаимодействие между JavaScript-кодом оболочки и Android.

Возможности:

* вызов Android-методов из JavaScript
* асинхронное выполнение операций с тайм-аутами
* передача данных между JavaScript и Android
* push-уведомления оболочке при изменении состояния ядра (`window.onCoreStateChanged`)

Встроенные API-методы:

* `GetApps` — список приложений
* `LaunchApp` — запуск приложения по пакету
* `GetStatusBar` — сигнал сети, Wi-Fi, батарея, температура
* `GetSystemInfo` — данные об устройстве
* `GetCoreState` — полное состояние ядра (тема, язык, ориентация, оболочка и др.)

Пример архитектуры:

```text
┌─────────────────────────────┐
│        Shell / WebView      │
│                             │
│       HTML / CSS / JS       │
└──────────────┬──────────────┘
               │
               │ JsBridge
               ▼
┌─────────────────────────────┐
│        Quty.Launch          │
│                             │
│  Android API / Storage /    │
│ Updates / Logs / Settings   │
└─────────────────────────────┘
```

---

### 🛒 Магазин оболочек (Store)

Встроенный магазин для установки и управления оболочками из удалённого каталога.

Возможности:

* каталог оболочек с превью, автором, версией, размером и датой
* статусы: «Активна», «Есть обновление», «Установлено»
* детальный экран с информацией и действиями
* установка, обновление и применение с прогрессом загрузки
* проверка совместимости по минимальной версии Quty.Launch
* раздел «Библиотека» для установленных ресурсов

---

### 🔄 Обновление приложения

Quty.Launch содержит инфраструктуру для обновления самого приложения:

* проверка наличия новой версии через сервер
* скачивание APK и установка через системный установщик
* локальная установка APK из файла
* авто-проверка обновлений по расписанию
* маркеры обновления в интерфейсе (badge)

---

### 🔄 Обновление оболочек

Оболочки могут самостоятельно проверять наличие обновлений через свой репозиторий:

* чтение `shell.json` из репозитория оболочки
* сравнение версий
* скачивание и установка новой версии

---

### ⚙️ Параметры и персонализация

Поддерживается управление основными параметрами приложения:

* ориентация экрана (авто / портрет / ландшафт)
* полноэкранный и строгий режимы
* тема оформления (светлая / тёмная / системная)
* выбор языка (русский / английский)
* цветовые схемы (9 вариантов)
* анимации (с учётом системного флага)
* назначение домашнего экрана (HOME-лаунчер)

---

### 🛟 Безопасный режим (Safe Mode)

Защита от «поломки» пользовательской оболочки:

* активация удержанием кнопки громкости
* принудительный запуск стандартной оболочки
* баннер в настройках с возможностью выхода
* сохранение выбранной пользователем оболочки до выхода из режима

---

### 🛠️ Режим разработчика (DevMode)

Расширенные инструменты для отладки и управления:

* активация серией кликов по версии приложения
* просмотр `manifest.json` активной оболочки
* перезагрузка оболочки
* очистка кэша WebView
* сброс онбординга и таймера обновлений
* управление видимостью Терминала и Логгера в списке приложений
* перезапуск приложения

---

### 🖥️ Терминал

Встроенная консоль ядра для диагностики и управления.

Возможности:

* выполнение команд ядра (не системных процессов)
* просмотр состояния ядра, версий, оболочек, хранилища
* вызов API-методов напрямую
* диагностика ядра (проверка разрешений, кэша, WebView и др.)
* история команд
* write-команды только при активном DevMode

---

### 📊 Логирование

Система логирования предназначена как для самого ядра, так и для оболочек.

Поддерживаются:

* уровни: DEBUG, INFO, WARN, ERROR
* теги подсистем (CORE, SHELL, WEBVIEW, API, UPDATE и др.)
* фильтрация по уровням и тегам
* буферизированная запись и ротация
* сохранение логов в файлы
* автосохранение при выходе
* просмотр, копирование и шаринг файлов логов
* раскрытие деталей записи (JSON) по тапу

---

### 💾 Резервное копирование и восстановление

Экспорт и импорт настроек приложения:

* сохранение в файл `.qutyconfig` (JSON) через SAF
* импорт с проверкой формата и версии
* полный сброс с очисткой данных, кэша и пользовательских файлов

---

### 🚪 Онбординг

Экран приветствия при первом запуске:

* динамический список разрешений с индикацией статуса
* прогресс предоставления разрешений
* переход к основному приложению после завершения

---

### 📁 Хранилище

Работа с файлами централизована через `StorageManager`.

Предусмотрено разделение данных проекта:

```text
Quty.Launch/
    ├── Logs/
    ├── Shells/
    ├── Updates/
    ├── Cache/
    └── Temp/
```

* `Logs/` — журналы работы приложения
* `Shells/` — пользовательские оболочки
* `Updates/` — загруженные обновления
* `Cache/` — кэш приложений
* `Temp/` — временные файлы

---

### 🔐 Безопасность

Quty.Launch использует стандартные механизмы безопасности Android:

* данные хранятся в изолированном хранилище приложения
* не требуется разрешение `MANAGE_EXTERNAL_STORAGE`
* для безопасного предоставления файлов используется `FileProvider`
* доступ оболочек к системным функциям осуществляется через контролируемый API-мост
* бэкапы и импорт выполняются через SAF

---

### ⚡ Производительность

Для уменьшения нагрузки на систему используются:

* буферизированная запись логов
* кэширование данных
* асинхронные операции с файлами
* фоновая обработка операций, не требующих немедленного ответа UI

## 📦 Формат Shell

Пользовательская оболочка распространяется в формате `.qutyshell`, `.qsp`, `.qutyshellpack`.

Файл представляет собой ZIP-архив со структурой, определяемой `manifest.json`.

Пример:

```text
MyShell.qutyshell
│
├── manifest.json
├── index.html
├── css/
├── js/
├── assets/
└── preview/
```

`manifest.json` содержит информацию об оболочке: название, автора, версию, превью, ориентацию, ссылки на репозиторий и Telegram, минимальную версию Quty.Launch и список используемых API-методов.

## 🧩 Назначение проекта

Quty.Launch создаётся как универсальная основа для приложений, где необходимо:

* быстро создавать собственные интерфейсы
* использовать HTML/CSS/JavaScript в качестве UI
* получать доступ к функциям Android через API
* подключать сменные оболочки
* централизованно управлять файлами
* реализовывать обновления
* получать диагностические логи

Главная идея проекта — **отделить системное ядро от пользовательского интерфейса**.

```text
                    Quty.Launch
                         │
        ┌────────────────┼────────────────┐
        │                │                │
        ▼                ▼                ▼
      Shell           Android API      Storage
        │                │                │
   HTML/CSS/JS       JsBridge        Logs / Files
        │                │                │
        └────────────────┼────────────────┘
                         │
                         ▼
                    Android App
```
